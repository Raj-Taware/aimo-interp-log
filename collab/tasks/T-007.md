# T-007 — Generation smoke test: trace length and accuracy per model

**Why.** Sizes the proposed H100 run that would label all four small models
ourselves (original + perturbed problems, several samples each). Claude's
estimate (~15M generated tokens per model) assumed ~3-4k-token traces; this
measures the real number before Raj commits H100 slots.

**Setup.** Kaggle T4x2, env per PROTOCOL rule 2 (pinned transformers /
accelerate, fp16). Plain `transformers` `generate`; no vLLM needed for this.

**Problems.** From `self-perturb/results/grok/T-006/answers.parquet`: the
same 10 for every model — 5 labelled robust and 5 spurious for DeepSeek
(robust labels: `aimo-interp/augmented-sample-math-agg`,
`model_is_robust`), chosen with `random.Random(0)`.

**Per model** (Qwen3.5-4B, Skywork-OR1-Math-7B, Olmo-3-7B-Think,
DeepSeek-R1-0528-Qwen3-8B):
- chat template, user turn = the problem, `add_generation_prompt=True`
  (no answer prefix — this is real solving);
- sampling `temperature=0.6, top_p=0.95`, 1 sample per problem, seed 0;
- `max_new_tokens=8192`; batch all 10 problems (left padding);
- extract the LAST `\boxed{...}` with balanced braces; correct = exact string
  match to the T-006 answer after stripping spaces and `$`.

**Report schema** (`collab/reports/T-007.md`) — one row per model:

| model | median tokens | mean | p90 | max | % hit 8192 cap | % with a \boxed | accuracy (of 10) | wall seconds | generated tok/s |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |

Plus: raw outputs to `self-perturb/results/grok/T-007/generations.jsonl`
(model, problem, tokens, finish_reason, extracted, correct), script
`self-perturb/scripts/gen_smoke.py`, commit. Stop a model early if it would
exceed 40 minutes and report how far it got.

## Note from Claude (reviewed `gen_smoke.py` at 80a8cfb, run in progress)

Script looks right. One risk to report on: `generate(eos_token_id=tokenizer.eos_token_id)`
overrides the model's `generation_config.eos_token_id`, which for some chat
models is a list including the turn-end token (e.g. `<|im_end|>`). If any
model shows a high "% hit 8192 cap" or outputs that continue past the
answer, add a column with `model.generation_config.eos_token_id` vs
`tokenizer.eos_token_id`; if they differ, rerun that model passing the
generation_config list. A cap-bound model would overstate the H100 cost.

## Review (Claude, 2026-10-02): done — numbers are protocol artifacts

From the raw generations:
- **Qwen3.5-4B**: the 3 runs that stopped answered in bold (`**33**`,
  `**34**`, `**31**`) — all correct; it was never asked for `\boxed`. The 7
  capped runs had reached correct answers (1024, 6, 0, ...) then looped
  ("I will write it.") without closing `</think>`. Stop tokens work
  (every stopped run has finish=stop).
- **DeepSeek**: text decodes as `dĠpointĠ(8,17)` — led to finding that
  transformers 5.13 strips all whitespace for this tokenizer
  (`self-perturb/docs/deepseek-tokenizer-bug.md`). Its runs read stripped text.
- **Olmo**: OOM from batching 10 x 8192-token generations on T4x2.
- **Skywork**: 9/10, median 1868 tokens — the one clean measurement.
Re-measured in T-009 with a fixed protocol, after T-008.
